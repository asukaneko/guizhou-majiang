# 贵州麻将：网页联机 · 贵阳捉鸡 / 幺筒麻将

一个能真正坐下来打的贵州麻将：108 张牌、碰 / 杠 / 胡、报听、抢杠胡、热炮、一炮多响。单机、联机都行。

进入游戏先是**游戏大厅**：看自己的资料与战绩、选玩法开桌。两种玩法各算各的账：

| 玩法            | 一句话                                                       |
| ------------- | --------------------------------------------------------- |
| **经典 · 贵阳捉鸡** | 四类鸡（幺鸡 / 乌骨鸡 / 翻牌鸡 / 金鸡）、冲锋鸡、责任鸡、包鸡，报听锁牌，抢杠热炮             |
| **幺筒麻将**      | 一筒当**财神**，能替任意一张牌；**冲幺筒**谁先打出去谁收分；没有鸡，硬胡额外加分              |
| **联机对战**      | 房主建房拿 4 位房号，朋友用房号进房；不满 4 人补机器人；服务端跑规则，出牌 / 碰杠胡 / 报听都在自己手里 |

牌面用的是公共领域的整套麻将矢量图（见下方「素材与许可」）。牌桌是 three.js 渲染的真 3D 桌面（three.js 本地引用、不联网），其余界面为原生 HTML/CSS/JS。

## 快速开始

```bash
cd guizhou-mahjong
npm install --omit=dev  # 网页服务器只需 ws，不安装 Electron
npm start              # 启动 HTTP + WebSocket，默认端口 8788
```

本机打开 `http://127.0.0.1:8788/`，朋友打开 `http://服务器IP:8788/`。网页默认进入游戏大厅，点击「联机对战」后连接本页服务器。

- **手机牌桌**：进入牌桌自动横屏排版；支持时尝试全屏与方向锁定，不支持时通过页面旋转显示横屏牌桌。旋转设备、浏览器地址栏展开/收起后重新计算可用空间。返回大厅或房间时恢复正常页面布局。
- **响应式页面**：大厅与房间使用正常页面宽度，窄屏可滚动；手牌和碰杠胡按钮按手机横屏重新排布。
- **掉线恢复**：在同一标签页刷新或临时断网后自动重连；服务端保留座位 60 秒，由电脑临时代打。恢复后使用原座位、手牌和累计分数；超时转为机器人，全部真人离开后清理房间。
- **连续开桌**：打满约定局数后返回房间，房主可调整玩法、局数和机器人，再点「开启新的一桌」。房号与现有座位保留，新桌从第 1 局开始并继承累计分；房主留在同一房间期间分数持续累加，主动退房后下一桌重新计分。房间内增删机器人实时同步。
- **回归验证**：`npm test` 覆盖规则、房间、真实 WS、网页消息与横屏逻辑；`npm run e2e` 验证两种玩法并行、六局换局、对局中恢复连接及原房重新开桌。手机真机视觉效果仍需设备验收。
- **3D 牌桌（three.js）**：桌面、木框、绒面、四方手牌、牌河、副露、桌心铭牌都渲染在 WebGL 里（`src/js/scene3d.js`，three.js 走本地 `src/vendor/three.min.js`，不联网）。牌是带圆角和倒角的薄片实体；三家对手的牌各自朝自己的方向立着，自己这一排则整排后仰、牌面正对镜头，所以自己的牌最清楚；摸到的牌单独空一格摆在牌列最右边，不并进手牌；牌河按 7 列网格平铺在手下沿，副露平摊在里面那条道上，桌心是同向的圆角方牌，靠透视相机和带阴影的主光得到近大远小和投影；点牌、悬停提示用射线拾取。机位约 30° 俯角、坐在桌边略往里收，自己的手牌占屏幕下方最大的一档。
- **听牌候选**：听牌时手牌右端会挂一排候选牌，每张角上标可见剩余张数（3D 牌桌下这排候选跟着 3D 手牌的右端定位）。
- **帧率显示**：牌桌左上角常驻一个小的实时帧率（`requestAnimationFrame` 采样，每 0.5 秒刷新，低于 45 变琥珀色），3D 和 DOM 兜底两套牌桌都显示。
- **DOM 兜底**：手机横屏、或者环境取不到 WebGL 时，自动退回原来的 CSS 牌桌（`#scene/#table`），布局和操作完全不变；座位信息牌、按钮、弹层、结算始终是 DOM，浮在 canvas 之上。

桌面客户端保留为兼容入口：需要时 `npm install`，再执行 `npm run start:desktop`。

- `start.bat` 是 GBK + CRLF 编码（中文 Windows 的 cmd 才能正确解析），会先清掉 `ELECTRON_RUN_AS_NODE` 再启动。
- 桌面入口 `npm run start:desktop` 通过 `scripts/launch.js` 清理 `ELECTRON_RUN_AS_NODE` 后启动。
- 桌面浏览器牌桌沿用 1200×740 布局并按窗口缩放；大厅与房间按实际宽度排版；手机采用独立横屏牌桌布局。

## 游戏大厅

网页默认进入游戏大厅，可查看战绩、选择玩法练习或进入「联机对战」（牌桌右上角「大厅」也可返回）：

- **玩家资料**：头像（点一下换）、昵称（点「改名」直接改，回车保存）、段位（按对局数升，从「新手上路」到「黔中雀神」，下面一条进度和「再打 N 局升到……」）。
- **分数**：生涯总分（两个玩法之和），以及各玩法单独的分数、局数、胡牌数。
- **对局数据**：对局 / 胡牌 / 胡牌率 / 最高连胜，最近一局的牌型与得失，最近 12 局的走势小方块（绿胡、红没胡、金跳黄庄）。
- **玩法选择**：两张模式卡，写明玩法要点与本模式战绩；牌桌还没打完的会显示「继续对局 · 第 N 局 · 你 +X」。
- **最近对局**：时间、玩法、结果（自摸 / 胡牌 / 没胡 / 黄庄）、牌型与分值、得分，最多 8 条（本地存 60 条）。
- 「清空战绩」会清掉生涯战绩、对局记录和两个玩法的牌桌分数；牌桌上的「清空分数」只清当前玩法的四家分数。

数据都存在本机浏览器存储里：`gz-mj-profile-v2`（资料 / 战绩 / 记录）、`gz-mj-table-classic` 与 `gz-mj-table-yitong`（各自牌桌上四家的累计分、局数、庄家）。旧版本只存经典模式的 `gz-mj-score` 会在首次启动时自动迁移。

## 怎么玩

- **出牌**：轮到你时，点手牌里的任意一张就打出去（悬停会抬起）。
- **听牌提示**：叫牌后，手牌右侧会以**手牌样式**列出所听的每一种牌，角标是这种牌的**可见剩余张数**（最多列 4 种，其余显示 `+N`）；鼠标停在一张手牌上还会显示「打这张 → 听什么、可见还剩几张」，并把手牌里能胡的牌高亮（金边）。
- **碰 / 杠 / 胡**：别人打牌后如果可操作，底部会明确提示「谁打出哪张」，按钮也标出牌名；牌河里最新弃牌会高亮并标注「可碰这张」。提示不会自动消失，直到你选择操作或点「过」（`Esc` 也可以过）。
- **暗杠 / 补杠**：在自己回合、出牌之前，按钮出现在同一位置。别人补杠的那张正好是你听的牌时，会弹出「可以抢杠」和「抢杠胡」按钮。
- **报听**：只能在本人首次出牌前、无副露且打牌可听时声明。系统替你打出保持听牌的那张，此后手牌锁定，不能碰杠，摸什么打什么，见胡就胡，胡牌额外 +20；起手13张就听牌并报听算**天听**（+40，替代报听加分）。头像旁显示「报听 / 天听」角标。
- **人机代打**：右上角「人机代打 开 / 关」（快捷键 `A`）。开启后电脑接管出牌、碰杠胡与抢杠，关闭后恢复手动操作；报听锁牌规则照常生效。联机时由服务端执行，换局后保留设置。
- **人机难度与速度**：简单 / 普通 / 困难三档，同时用于机器人和人机代打。本地在大厅「本地练习」选择，也可在牌桌顶部切换，选择自动保存。联机由房主在建房或局间选难度，在房间或牌桌顶部设置慢 / 中 / 快速度；局中调速同步给全房间，真人操作超时仍为出牌 60 秒、抢牌 20 秒，配置随重连、换局和原房开新桌保留。
- **新的一局**：手机横屏及全屏时顶部也可操作。本地可直接开始新局，保留累计分；联机需非房主真人准备齐全，房主才能在本局结束后开下一局。
- **速度**：右上角「速度 慢 / 中 / 快」切换电脑出牌节奏。
- **庄家**：胡牌者接庄，黄庄庄家连庄。

## 幺筒麻将

一筒就是**幺筒**，也是这桌的**财神**：

![幺筒麻将](output/yitong.png)

- **替牌**：手里每张幺筒都能替代任意一张牌去凑牌型——顺子缺张、刻子缺张、将缺一张都行；也可以当真一筒用（凑 123 筒、当刻子、当将），哪种划算按哪种算。
- **软胡 / 硬胡**：胡牌时用了替身就是**软胡**（牌型分照常）；一张替身都没用（幺筒全当真一筒，或者手里压根没幺筒）就是**硬胡**，胡牌分 **+5**。结算面板上会挂「硬胡 / 软胡」标签。
- **冲幺筒**：本局**第一张**被打出的幺筒，打牌者向其他三家**各收 5 分**；**第二张**各收 **3 分**；第三、第四张没有冲分。先冲先赚——冲出去就少一张财神，自己权衡。手里有幺筒时，底部会有一条金色提示「冲幺筒 · 打出 一筒 向三家各收 N 分」，鼠标悬停在那张幺筒上也会写。
- **不能碰、不能杠**：幺筒是财神，不成坎；手里四张也不弹暗杠。
- **没有鸡**：幺鸡、八筒在这里只是普通牌，不算鸡、不翻牌、没有包鸡。结算只看胡牌分 + 豆 + 冲幺筒。
- 牌型分值、自摸 / 杠上花、天胡地胡、报听天听、抢杠、热炮、一炮多响、豆、黄庄查叫、吃炮通行证都和经典一致。

## 电脑决策

机器人和人机代打共用 `src/js/ai.js`，本地与联机使用相同策略：

| 难度     | 决策                                 |
| ------ | ---------------------------------- |
| 简单     | 比较刻子、顺子、对子和搭子的基础评分，直接选择合法碰杠        |
| 普通（默认） | 向听数、可见进张、有限前瞻及公开信息风险，前瞻上限 3×6×2    |
| 困难     | 前瞻上限提高至 5×12×3，提高弃牌风险权重，并在较早阶段考虑防守 |

- **记忆化向听数**：分门枚举面子、搭子与将，动态合并；同时比较普通胡和七对，支持四归二与幺筒财神。
- **有效进张**：用本人手牌、公开副露和牌河计算可见剩余张数；已经耗尽的等待牌不计入进张。
- **有限宽度期望前瞻**：普通档根部保留 3 个弃牌候选，每个最多展开 6 种有效摸牌、2 种后续弃牌；困难档上限为 5×12×3，缓存与固定展开上限控制耗时。
- **碰杠收益**：比较操作前后的向听数和进张，并考虑豆分、责任鸡、抢杠风险；保护七对与已有听口。
- **公开信息风险**：参考报听、公开副露和可见牌形估计危险度。风险为启发式估计，不使用日麻振听规则判断绝对安全牌。
- **幺筒冲分**：将即时收益纳入选择，散牌时可用一步进度换冲分，听牌时优先保留有效听口。

AI 输入不含其他玩家手牌、他人暗杠牌面或牌墙顺序。向听数与有效牌的背景可参阅 [A Fast Algorithm for Computing the Deficiency Number of a Mahjong Hand](https://arxiv.org/abs/2108.06832)；本项目采用独立实现并适配当前两种玩法。

## 联机对战

一台机器当服务器，大家连同一个局域网就能开桌：

![联机面板](output/online.png)

- **启动服务器**：`npm run server`（或 `node server/index.js --port=8788`）。启动后会把本机和局域网地址都打出来；同一个端口也是 HTTP 静态页，浏览器打开 `http://IP:8788` 就能玩，不用装任何东西。
- **建房**：大厅 → 联机对战 → 连接服务器 → 「创建房间」，选好玩法和局数，拿 4 位房号。
- **加入**：朋友在联机面板输入房号「加入房间」，或直接点房间内空位复制的邀请链接。链接带 `?room=4321`，打开后自动进房；看到座位列表、谁是谁、谁是房主。
- **机器人**：房主点「添加机器人」补空位（可移除）；对局中真人掉线，该座位自动转电脑代打，不坑局。
- **开局**：满员后房主点「开始对局」。每局结算后，非房主真人点击「准备」，机器人自动就绪；全部准备后房主点「开始下一局」，打到约定局数为止。可取消准备，结算页和房间页实时显示状态，顶部开局入口使用相同限制。
- **准备状态**：每局结束重新确认，人机代打的真人也需要手动准备。临时掉线保留已准备状态，恢复在线后才能开局；房主转移后按新身份确认。玩法、局数或难度变更时重新准备，单独调整速度保留准备。原房新桌同样等待准备齐全。
- **新桌**：约定局数打满后点「返回房间」，房主重新配置并点击「开启新的一桌」，沿用同一房号和座位，继承累计分，局数与庄家重新开始。
- **房间聊天**：房间页设有明确的聊天入口，与牌桌共用记录。PC 房间和对局默认显示右侧聊天区，点面板「折叠」或顶部「聊天」收起，再点按钮展开，页面与牌桌会释放并重新利用空间；两个页面分别记住本次打开期间的折叠选择。手机和窄屏通过房间内或顶部按钮展开覆盖面板。支持未读提示、快捷短语、Enter 发送及草稿保留；每条最多 200 字，重连补发最近 100 条，同房间跨桌保留。
- **房间页面**：集中显示房号、入座人数、准备进度和开局操作；四个座位按本人视角排列，显示昵称、身份及累计分。空位整张卡片可点，房主和普通玩家都能一键复制「邀请码 + 可点击入房链接」；桌面端没有网页地址时退化为复制房号说明。窄屏以两列排列座位和设置，房主配置及准备权限与服务端保持一致。
- **公平性**：服务端是权威端——`rules.js`/`game.js` 在 Node 里跑同一套规则；发牌、摸牌都在服务器，快照按座位轮转（你永远坐 0 号位），**对局中隐藏别人的手牌和暗杠牌面**；本局结算后公开四家牌面。出牌 / 碰杠胡 / 报听 / 抢杠都是你自己在客户端点。
- **超时兜底**：出牌 60 秒、吃碰胡 20 秒没响应，服务器自动代打/放弃，不卡整桌。
- 联机对局也记入大厅的「最近对局」与生涯战绩（本机视角的得分），牌桌分数以服务器为准。

## 规则实现范围（经典 · 贵阳捉鸡）

| 项目      | 实现                                                                                                              |
| ------- | --------------------------------------------------------------------------------------------------------------- |
| 牌张      | 108 张（万/条/筒 1-9，各 4 张），无字牌无花牌                                                                                   |
| 操作      | 碰、明杠、暗杠、补杠、胡、报听、抢杠胡；不能吃                                                                                         |
| 牌型      | 平胡4、大对子14、七对24、龙七对44、双龙七对64、三龙七对84；清一色24、清大对34、清七对44、清龙七对64、清双龙七对84、清三龙七对104。均含4分胡牌底分，只取最高牌型                    |
| 附加      | 自摸 +1、杠上花 +1、热炮 +20；素摸 +10（自摸且手牌 / 副露 / 自己牌河一张鸡都没有，幺鸡、八筒、翻牌鸡都算鸡）；天胡 +60、地胡 +30；报听 +20、天听 +40、抢杠胡 +20。天听替代报听，其余按满足条件相加 |
| 吃炮门槛    | 普通吃炮要求基础牌型分至少14分，杠牌、报听或硬胡不改变此门槛；抢杠胡不受限                                                                          |
| 豆（杠）    | 操作时只记账，胡牌时统一结算。杠家听牌：暗杠 / 补杠向其他三家各收4分，明杠向原放杠者收4分；杠家未听：每个杠向每位听牌者各赔4分                                              |
| 报听 / 天听 | 本人首次出牌前、无副露时声明，之后锁牌；起手13张听牌并声明为天听。已打出的牌被碰杠拿走也不能恢复声明资格                                                           |
| 天胡 / 地胡 | 天胡：庄家第一摸就自摸；地胡：下家第一巡自摸或胡庄家首张                                                                                    |
| 抢杠胡     | 被抢的补杠不成立，补杠者向每位胡家各付一份胡牌分                                                                                        |
| 热炮      | 杠后打出的牌被别人胡，胡牌分 +20                                                                                              |
| 一炮多响    | 一张牌被两家以上胡，所有人都算胡，点炮者各赔一份，鸡分别结算                                                                                  |
| 鸡       | 胡牌时统一结算。幺鸡（一条）与乌骨鸡（八筒）均为2分/张，翻牌鸡1分/张；金鸡翻倍为4分/张；冲锋鸡计双倍——幺鸡和八筒各算各的（同一局可以分别冲），第一轮（开局前4张出牌）内跟打已经冲过的那种鸡也算冲锋鸡（跟冲）。听牌者按本人手牌、副露和牌河的鸡分向其他三家各收一份；未听者只按自己**牌河**里的常鸡分向每位听牌者各赔一份（手里的、副露里的鸡都不赔，翻牌鸡也不算，包含未胡牌的听牌者） |
| 责任鸡     | 冲锋鸡被碰 / 杠走时只记2分，这张不再翻倍（跟冲的那张被拿走只是不再翻倍，不记责任鸡）。胡牌时拿牌者听牌，原出牌者向其付2分；拿牌者未听，则向每位听牌者各赔2分                          |
| 黄庄      | 杠和责任鸡作废，不翻牌、不结算普通鸡分，只进行查叫：未听者分别赔给每位听牌者其最高基础牌型分，不加报听、天听或硬胡。已发生的冲幺筒流水保留                                           |
| 结算展示    | 牌型、胡牌分与各项加分、翻牌与鸡（含冲锋鸡 / 包鸡）、杠与责任鸡实际收支、四家本局与总分（恒为零和）；一炮多响逐家列出。点击“查看牌面”可展示四家手牌和暗杠，再点“返回结算”回到弹窗；支持 PC 和手机横屏        |

本地与联机共用 `rules.js` 和 `game.js` 的计分配置，规则面板直接读取牌型与加分常量。七对按实牌中的四张同牌组数区分龙、双龙、三龙；胡牌底分已包含在牌型分中。

自动化用例覆盖：

- 各牌型分值与「取最高不叠加」
- 副露参与判定、副露后不算七对
- 听牌张与查叫分值
- 吃炮通行证
- 庄家首轮只摸一次、手牌数为 14 张（防止庄家多摸一张导致胡牌判定失效）
- 鸡的分值（一条2 / 八筒2）、金鸡翻倍、副露按张数计鸡
- 整局模拟 8 局：无异常、每局四家分数零和、黄庄数据结构完整
- 玩家侧动作路径：碰 / 杠 / 胡 的响应与结算
- 人机代打：未听牌也能接管、取消后交回手动、碰杠胡与抢杠自动处理、整局无需手动提示、真实联机连续换局保留设置
- 报听：锁牌、天听判定、出张；报听后整局不再要求手动出牌
- 报听 / 天听 / 天胡 / 热炮 / 抢杠的加分与包赔
- 天胡 / 地胡的判定条件
- 抢杠胡：杠不成立，补杠者向每位胡家各付一份
- 热炮：杠后打出的牌被别人胡
- 一炮多响：一张牌两家胡、点炮者各赔一份
- 冲锋鸡双倍、责任鸡赔豆、包鸡反向赔付
- 含新规则的 6 局整局模拟：分数仍为零和
- 幺筒模式：一筒替牌能胡、经典模式不能；听牌多出一筒；硬胡 +5 进结算且本模式没有鸡
- 幺筒不能碰、不能杠（手里四张也不弹暗杠）
- 冲幺筒：首张向三家各收 5 分、第二张 3 分、第三张不收，且零和
- 玩法切换：两套规则各算各的（`MODES` / `CHICKEN_SET`）
- 联机：建房 / 加入 / 机器人 / 满员 / 房主转移；快照按座位轮转（人人 0 号位）且不下发他人手牌与暗杠；两真人+两机器人连打两局零和；非法操作（别人的回合、不存在的牌、乱胡）全被拒
